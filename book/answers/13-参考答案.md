# 第 13 章 参考答案

## 练习 1：跳过前置角色

```powershell
$env:L2_SKIP_ORDER="1"; go run ./cmd/l2
```

预期观察：

- 被拒绝的是 `outline`（或 `design` / `render`，取决于 Mock 先尝试谁）；
- 错误信息类似："前置产物未就绪：缺少 research。请先调用对应工具产出它们"；
- 模型会收到这条结构化错误，然后重新调度。

关键点：拒绝来自 `missingNeeds()`，不是 Prompt。即使模型"很想"跳过，也调不通。

## 练习 2：触发熔断

一个总是失败的 SubAgent：

```go
type AlwaysFail struct{}

func (AlwaysFail) Name() string { return "always-fail" }
func (AlwaysFail) Kind() schema.Kind { return "outline" }
func (AlwaysFail) Description() string { return "总是失败" }
func (AlwaysFail) Needs() []schema.Kind { return nil }
func (AlwaysFail) Run(context.Context, SubAgentInput) (schema.Payload, error) {
    return nil, fmt.Errorf("模拟失败")
}
```

把它包装成工具，连续调用 4 次：

- 第 1 次：`执行失败（连续第 1 次）`；
- 第 2 次：`连续第 2 次`；
- 第 3 次：`连续第 3 次`；
- 第 4 次：在依赖检查之前返回"已连续失败 3 次，已被熔断"。

熔断信息给了三条出路：换角色、换策略、结束并说明卡点。

注意：计数是**连续**的，成功一次就清零。它不是"累计失败次数"。

## 练习 3：制造过期上游

步骤：

1. `research`、`outline`、`design` 各一版；
2. 重跑 `outline`，产出 `outline@2`；
3. 调用 `renderer`。

预期：`renderer` 的 `staleInputs` 会检查它需要的 `outline` 和 `design`：

- `outline@2` 是最新，没问题；
- `design@1` 依据 `outline@1`，而最新是 `outline@2`，所以过期。

错误信息里会指出 `design` 过期，修复顺序是**先 design，再 render**。这正是 `StaleReasons` 后序遍历给出的可执行顺序。

## 练习 4：为什么参数只有 hint

如果加上 `inputs` 字段：

```go
type subAgentArgs struct {
    Hint   string `json:"hint"`
    Inputs string `json:"inputs"`
}
```

风险：

- Supervisor 会把上游 JSON 塞进 `inputs`，开始做"逐字段提取重组"；
- 一旦它开始搬数据，就会丢字段、改字段、编字段；
- 这些错误不会在协议层暴露，只会在下游变成"内容不对"。

"没有字段可搬"比"Prompt 说不要搬"更可靠，因为它把约束从**建议**变成了**类型系统的一部分**。

## 练习 5：统计口径

假设第一次失败（消耗 1000 token），第二次成功（消耗 500 token）。

- 如果 `Stats()` 返回"最近一次"：结果是 500；
- 如果返回"累计"：结果是 1500。

成本核算要的是 1500。失败的那 1000 token 也花了钱。

L2-3 的 bug 就是子 Agent 用覆盖、编排者用累加，导致"返工最多的角色反而算得最少"。修复后统一为累计。

## checkpoint 的简要答案

- **五个方法**：Name（我是谁）、Kind（产出什么/工具名/key）、Description（何时调我）、Needs（依赖谁）、Run（怎么做）。
- **Kind 三合一**：保证路由、产物类型、黑板 key 一致，一层校验管三件事。
- **四道检查**：熔断 → 依赖 → 新鲜度 → Kind 一致性；顺序按"最不可恢复/最便宜"排。
- **熔断**：防止模型换措辞反复重试同一个根因；放在最前，因为它是最强信号。
- **BasedOn 由适配器填**：它同时握着 Artifact 和版本；子 Agent 只有字符串 ref。
- **Reader 只读**：不需要写的能力就不给，类型上消除误用。
- **L3**：依赖检查由结构保证；新鲜度、熔断、Kind 校验仍然存在。
