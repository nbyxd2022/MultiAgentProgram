# 第 17 章 参考答案

## 练习 1：加一个节点

```go
type FactCheck struct{}

func (FactCheck) Name() string { return "fact-check" }
func (FactCheck) Kind() schema.Kind { return "fact_check" }
func (FactCheck) Description() string { return "核对大纲中的事实" }
func (FactCheck) Needs() []schema.Kind {
    return []schema.Kind{schema.KindResearch, schema.KindOutline}
}
func (FactCheck) Run(ctx context.Context, in graph.NodeInput) (*graph.Outcome, error) {
    return &graph.Outcome{Product: schema.Research{
        Topic: in.Topic,
        Findings: []schema.Finding{{Claim: "已核对", Source: "fact-check"}},
    }}, nil
}
```

注意：`Kind()` 必须是一个**合法的** Kind；`fact_check` 不在 `Kind.Valid()` 的词表里，所以真实代码里需要先扩展 `schema.Kind` 与 `Valid()`。这个练习的重点是让你发现：

- 加节点不只是加一个 struct；
- 新 Kind 要同步扩展受控词表、payload 类型、`Valid()`、`Decode`。

观察（假设 Kind 已合法）：

- `Edges()` 多出 `research → fact-check`、`outline → fact-check`；
- `Order()` 里 fact-check 排在 research 和 outline 之后；
- `Layers()` 里它取决于依赖深度。

## 练习 2：删掉一个生产者

把 `outline` 节点删掉，但保留 `designer`（`Needs` outline）。

`BuildGraph` 会在建图期报：

```text
节点 designer 依赖 "outline"，但没有节点产出它、它也不在预置输入里 —— 这条前置永远不会就绪
```

这条错误直接告诉你"该加哪个节点"，不需要跑到运行期。

## 练习 3：制造一个环

A `Needs` B，B `Needs` C，C `Needs` A。

`topoSort` 遇到 gray 节点，`cyclePath` 输出：

```text
图里有环：a → b → c → a
```

如果没有 `cyclePath`，你只知道"有环"，但不知道是哪几个节点咬住了。排查会从"看路径"变成"逐个试"。

## 练习 4：两个节点产出同一个 Kind

错误：

```text
节点 A 与 B 都产出 "outline"：它们会抢同一个黑板 key
```

为什么破坏版本语义：

- A 写 `outline@1`，B 写 `outline@2`，A 再写 `outline@3`；
- `Get("outline@2")` 取到的是 B 的产物；
- 下游 `BasedOn: outline@2` 以为是 A 的产物（因为它只知道 key，不知道谁写的）；
- 两个产物的 `Kind` 都是 `outline`，`Decode` 的双向校验也发现不了来源错位。

## 练习 5：非法的 Next

节点返回 `Next = "render"`，但图里没有 `outline → render` 的边。

`CheckOutcome` 报：

```text
节点 outline 想跳到 "render"，但图里没有这条依赖边 —— "render" 并不需要 "outline" 的产出。
要允许它，请让 render.Needs() 里包含 "outline"（边会自动出现）；
或者在节点内部把这次跳转改成重做自己
```

按提示把 `outline` 加进 `render.Needs()`，边会自动出现。

为什么"改 Needs"比"改边"更好：

- 边只有一个来源，不会出现"改了 Needs 忘了改边"；
- 前置检查、工具描述、图拓扑三处自动同步；
- 修法就是改声明，不需要在另一个地方维护第二份事实。

## checkpoint 的简要答案

- **顺序来源**：L2 是模型试 + 代码拒绝；L3 是依赖推导 + 拓扑排序。
- **边由 Needs 推导**：单一来源，加角色只改一处，并行是白拿的。
- **没有游标**：完成是产物属性，"下一步"可从 `CanSkip` 算出来。
- **Next 两种合法情况**：跳自己（重做）；跳到有边的下游。
- **CheckOutcome**：只校验结构（节点存在、边存在），不校验重试次数/预算。
- **Layers 只是候选**：Runner 串行，并行要处理交付、隔离、合并。
- **没有 Edge.When**：避免两套条件机制；节点级判断用 `Outcome.Next`。
