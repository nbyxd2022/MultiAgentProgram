# 第 23 章 参考答案

## 练习 1：加一种事件

一个可能的设计：

```go
KindCacheHit Kind = "cache_hit"
```

它属于 `LayerLLM`（模型调用的缓存命中），需要 `Phase`，不需要用量/工具/对账。

要同步改：

1. `kindSpecs` 加一条 `{NeedsPhase: true, Desc: "模型缓存命中"}`；
2. `AllKinds()` 自动包含它（从同一张表派生）；
3. `TestKindVocabularyIsSelfConsistent` 会检查描述非空；
4. 如果有消费者需要区分，再加字段。

为什么不是只加一个常量？

- 没有 `kindSpec`，`Validate` 不会校验它；
- 错误信息可能列不出它；
- 聚合代码可能不认识它；
- "声明了但没人读"的半成品就是这样产生的。

## 练习 2：制造非法事件

`Recorder` 会把事件收下，同时把错误记进 `Invalid()`。

为什么收下而不是拒绝？

观测的第一职责是"如实记录正在发生什么"；拒绝会让"究竟发生了什么"更难查（少了那一条）。

校验失败只记账，由测试断言 `Invalid()` 为空。

这体现了一个分工：

- 生产出口：不校验（没有预算）；
- 开发出口：校验（事件量小、出错要立刻知道）。

## 练习 3：从事件派生统计

```go
steps := rec.Count(observ.KindStart)
toolCalls := rec.Count(observ.KindToolCall)
p, c := rec.Usage()
```

如果另存一份 `Stats`：

- 两边各自累加同一些数；
- 谁都不会报错；
- 它们会慢慢不一致；
- 一旦不一致，你不知道该信哪一份。

所以仓库让 `Stats` 从事件流派生：**只能有一份明细**。

## 练习 4：给 Detail 加一个派生值

如果 `Detail` 写"第 3 步"：

- 恢复后，步号可能从 0 重新数，数字不对；
- 两次运行的 diff 会多出一堆噪声；
- 它不是一个"发生的事实"，而是一个"可以被算出来的值"。

规则：**能被算出来的，不许写进 Detail。** 让消费者用 `KindStart` 的条数去算。

## 练习 5：设计一个 Reconcile

```go
observ.Reconcile{
    What:     "页数",
    Declared: 3,
    Actual:   2,
}
```

`Diff()` 输出：

```text
页数：声明 3，实际 2（少 1）
```

为什么不能只报 `mismatch: true`？

因为"不对"不告诉你差在哪、差多少。排查需要方向与幅度。

事件应该属于 `LayerGraph`，`Phase` 是 `render`（或渲染节点名）。

## checkpoint 的简要答案

- **强类型 vs 自由字符串**：拼错后果重（聚合/键）→ 强类型；只用于显示的数据 → 自由字符串。
- **kindSpec**：只约束"缺了它就没意义"的字段；不约束所有字段。
- **没有 Seq/总数**：它们是派生值；存了就要维护，维护就会漏。
- **Detail 边界**：自由文本会吸引本该结构化的东西；能算的不许写。
- **Reconcile**：捕捉"流程成功但内容不对"的静默错误。
- **Behavior**：只覆盖行为，不覆盖环境；算多会永远红，算少会假绿。
- **Tracer 不返回 error**：观测失败可重建，不该拖垮业务。
