# 第 28 章 参考答案

## 练习 1：分类三条差异

### 缺陷：panic 没有 recover

能写出会失败的测试：

```go
func TestNodePanicBecomesError(t *testing.T)
```

断言：节点 panic 时，Runner 返回 error，而不是进程崩溃，且错误里带 stack。

### 欠账：模型调用的 fallback 链

能写出测试（给定一个 429/5xx，期望切换到备用模型），但依赖还不存在：

- 没有备用模型配置；
- 没有真实模型调用；
- 没有价格/限流数据。

所以登记 + 触发条件："接真实模型跑评测时"。

### 取舍：滑动窗口 vs 累计上限

写不出会失败的测试：累计上限同样能拦住"总量超了"。

差别只在突发流量，而 CLI 单进程没有突发流量。保留累计上限。

## 练习 2：一条会失败的测试

```go
func TestOpenAI429IsRetryable(t *testing.T) {
    err := &llm.HTTPStatusError{StatusCode: 429}
    if !errclass.CanRetry(err) {
        t.Fatal("429 应该可重试")
    }
}
```

当前代码里，`openai.go` 返回的是普通 `fmt.Errorf`，`errclass` 会归为 `Permanent`——所以这条测试今天就会失败。

## 练习 3：空壳

以 `CostMilli` 为例：

- 它要报告的事实：这次调用花了多少钱；
- 谁应该生产：拥有价格表的那一层（装配/适配器），在每次成功调用后计算；
- 没有它：预算的"成本"维度永远是 0，看起来有、实际没有。

其他候选：

- `KindReconcile`：没有生产点；
- `Layers()` 的并行：只是候选，Runner 串行；
- `LocalAndRemote`：有实现、有测试，但没有生产接线。

## 练习 4：注释能不能抄

以 TOCTOU 注释为例：

- 前提：HTTP 服务、真并发、多个请求同时 Allow；
- 我们的前提：CLI 单进程、图串行；
- 照抄的后果：下一个人以为"我们也有这个窗口"，于是可能引入不必要的预留/结算复杂度，或者反过来以为"已经考虑过了"。

## 练习 5：不抄清单

1. **25 个错误类型**：业务表，不是形状；
2. **滑动窗口限流**：问题不同（速率 vs 总量）；
3. **`min(Remaining)`**：单位不同，不能比大小；
4. **OTel/Prometheus 具体接入**：端口先定，适配器后补；
5. **业务 Prompt 措辞**：它的业务 schema 与我们不同。

## checkpoint 的简要答案

- **不能逐文件对齐**：规模、抽象、依赖都不同；按"关心的事"比。
- **三分法**：缺陷（能写失败测试）/ 欠账（能写但依赖缺失）/ 取舍（写不出）。
- **值得抄的形状**：panic 边界、超时生产者、错误分类、重试退避、原子写、端口-适配器、结构化错误。
- **25 个错误类型**：那是业务表；抄形状不抄表。
- **不能直接抄**：滑动窗口（速率 vs 总量）、min（单位不同）、TOCTOU（并发前提不同）。
- **空壳**：有声明/实现，没有生产者；比没实现更危险，因为看起来有。
- **五步**：读 why → 写失败测试 → 抄形状 → 注入验证 → 记录触发条件。
