# 第 27 章 参考答案

## 练习 1：给四个注入分类

| 注入 | 现象 | 分类 | 下一步 |
|---|---|---|---|
| `L4_BAD_CASE=1` | 期望 99 页，实际 3 页 | E 错位/契约不符 | 这是故意的注入，确认汇总在算 |
| `L4_JUDGE_REFUSES=1` | 第一次软判据非法，回灌后改对 | F 评审/提交失败（已自愈） | 看 `healed` 次数；若自愈失败，看 `JudgeErr` |
| `L4_HUGE_TOKENS=outline` | prompt 预算触顶 | G 成本/预算 | 看 `Decision.Notice` 与已完成产物 |
| `L4_LOOP_FOREVER=outline` | 达到最大步数 8 | A 未跑完（根因 G） | 看节点为什么会无界重试 |

注意：同一个现象可以同时有"表层分类"和"根因分类"。报告时最好写：

```text
分类：A（未跑完）
根因：G（节点重试无界）
```

## 练习 2：失败卡

模板：

```text
run id: l4-2026-10-22-01
case id: baseline-3p
结果: fail
分类: D（过期）
失败判据: must_have_kinds（缺 render）
关键指标: steps=4 / agent_steps=18 / tokens=8200 / wall=12s
一句话根因: outline 重跑后，design 依据的 outline@1 过期，renderer 被前置检查拒绝
下一步: 按 StaleReasons 顺序先重跑 design，再重跑 renderer
```

要求：

- 分类只能选一个（根因可以另写）；
- 根因一句话；
- 下一步是一个动作。

## 练习 3：找一次"分类错误"

场景：最终输出缺了一页。你以为是"模型不行"，实际是"design 基于旧 outline"。

只看最终输出，你无法区分：

- 模型没生成；
- 生成了但被下游丢掉；
- 生成了但过期；
- 产物存在但 Kind 错。

需要：

- `Board`（有哪些产物、版本）；
- `BasedOn`（血缘）；
- `StaleReasons`（是否过期）；
- `Shortfall`（是否完整）；
- 事件流（哪个节点跑了、哪个被跳过）。

## 练习 4：给 `Verdict` 加 `FailureKind`

```go
type Verdict struct {
    ...
    FailureKind string
}
```

- 谁来填：`runOne` 在判据失败/错误分类时填；
- 填错：统计会失真，所以要有测试；
- 不能替代 `Failed []string`：`Failed` 是"哪条判据、期望、实际"，`FailureKind` 是"哪一类"，两者粒度不同。

## 练习 5：20 次实验计划

- 用例：10 条（覆盖不同主题与边界）；
- 每条跑 2 次（共 20 次）；
- 固定模型、温度、预算、commit；
- 记录：pass/fail/error、分类 A~H、steps、agent_steps、tokens、wall；
- 判断"变好"：不是看单次平均，而是看**分类分布**与关键指标的置信区间；至少同一组用例前后各 20 次。

## checkpoint 的简要答案

- **通过率不够**：它不告诉你失败类型和下一步。
- **A~H**：未跑完、缺产物、不完整、过期、错位、评审/提交失败、成本/时间、恢复/HITL。
- **三判据**：可行动、互斥、能计数。
- **未跑完 vs 判据没过**：前者看 error，后者看产物。
- **按影响排序**：频率、成本、是否阻塞其他修复。
- **软判据平均分**：概率线索，不能指导下一步。
- **固定变量**：用例、模型、温度、预算、commit。
