# 第 10 章 参考答案

## 练习 1：验证追加与深拷贝

```go
b := state.NewBlackboard()

a1, _ := schema.NewArtifact("note", "code", schema.Topic{Text: "第一版"})
a1, _ = b.Put(a1)
fmt.Println(a1.Version) // 1

a2, _ := schema.NewArtifact("note", "code", schema.Topic{Text: "第二版"})
a2, _ = b.Put(a2)
fmt.Println(a2.Version) // 2

v1, _ := b.Get("note@1")
v2, _ := b.Get("note@2")
fmt.Println(string(v1.Payload)) // {"text":"第一版"}
fmt.Println(string(v2.Payload)) // {"text":"第二版"}

// 改返回值，不影响黑板
v1.Payload[0] = 'X'
again, _ := b.Get("note@1")
fmt.Println(string(again.Payload)) // 仍然是 {"text":"第一版"}
```

预期：

- 两次 `Put` 的版本分别是 1、2；
- `@1` 和 `@2` 都能取到，且内容不同；
- 修改 `Get` 返回的 `Payload` 不会污染黑板。

## 练习 2：构造一条血缘链

```go
b := state.NewBlackboard()

topic, _ := schema.NewArtifact("topic", "code", schema.Topic{Text: "新能源汽车"})
topic, _ = b.Put(topic)

research, _ := schema.NewArtifact("research", "research", schema.Research{
    Topic: "新能源汽车",
    Queries: []string{"渗透率"},
    Findings: []schema.Finding{{Claim: "渗透率 35%", Source: "mock"}},
})
research.BasedOn = []schema.Basis{schema.BasisOf(topic)}
research, _ = b.Put(research)

outline, _ := schema.NewArtifact("outline", "outline", schema.Outline{
    Pages: []schema.PageOutline{{Index: 0, Title: "趋势", Points: []string{"渗透率"}}},
})
outline.BasedOn = []schema.Basis{schema.BasisOf(research)}
outline, _ = b.Put(outline)

// 重跑 research，产出 @2
research2, _ := schema.NewArtifact("research", "research", schema.Research{
    Topic: "新能源汽车",
    Queries: []string{"渗透率", "成本"},
    Findings: []schema.Finding{{Claim: "渗透率 40%", Source: "mock"}},
})
research2.BasedOn = []schema.Basis{schema.BasisOf(topic)}
research2, _ = b.Put(research2)

latest := func(key string) (schema.Artifact, bool) {
    a, err := b.Get(key)
    return a, err == nil
}

reasons := schema.StaleReasons(outline, latest)
fmt.Println(reasons)
```

预期输出（大致）：

```text
[outline：outline@1 依据的 research@1 已经更新到 research@2（产出者 outline，请重新调度它）]
```

如果你再加一个 `design@1`（BasedOn `outline@1`），并对 `design` 调用 `StaleReasons`，输出会先包含 outline 的过期原因（因为它会先走到 outline），这说明：

- 后序遍历先报上游；
- 下游的"间接过期"可能只体现为上游那条原因，而不是单独一条"design 过期"。

只要 `len(reasons) > 0`，就说明这份产物不能直接用。

## 练习 3：ParseRef 的边界

| 输入 | key | version | err |
|---|---|---|---|
| `outline` | `outline` | 0 | nil（0 表示取最新） |
| `outline@2` | `outline` | 2 | nil |
| `outline@0` | | | 版本必须是正整数 |
| `outline@x` | | | 版本必须是正整数 |
| `@1` | | | 缺少 key |
| `""` | | | 引用为空 |

注意：`version=0` 不是错误，它表示"未指定版本，取最新"。这是给人用的查询方式；流程里的引用应该始终带版本。

## 练习 4：设计一个 Summary

```go
func (o Outline) Summarize() string {
    titles := make([]string, 0, len(o.Pages))
    for _, p := range o.Pages {
        titles = append(titles, p.Title)
    }
    return fmt.Sprintf("outline：%d 页 %s", len(o.Pages), joinShort(titles, 4, 90))
}
```

这个摘要：

- 包含页数；
- 包含前几页标题；
- 不包含每页的全部要点；
- 总长有上限。

`RenderResult` 的摘要：

```go
func (r RenderResult) Summarize() string {
    s := fmt.Sprintf("render：%d 个文件 %s", len(r.Files), joinShort(r.Files, 4, 110))
    if len(r.Failed) > 0 {
        s += fmt.Sprintf("；%d 页未产出", len(r.Failed))
    }
    return s
}
```

失败必须出现在摘要里，否则下一跳会以为"全都成功了"。

## 练习 5：什么时候该有 Shortfall

| 情况 | 该有 Shortfall 吗 | 理由 |
|---|---|---|
| 3 页成功 2 页，第 3 页写盘失败 | 该 | 产物存在，但不完整 |
| research 找到 0 条发现 | 不该（或单独判据） | "0 条"是完整结果的一种，不是"缺了几条" |
| outline 只有 2 页，期望 3 页 | 不该用 Shortfall，应该 Validate 报错 | 页数不对是契约不满足，不是"部分完成" |

`Shortfall` 的语义是"我产出了，但有一部分没出来"；"数量不对"和"完全没有"应该用别的判据。

## checkpoint 的简要答案

- **map 的问题**：覆盖旧版、没有引用、没有血缘、无法判断新鲜度、无法审计。
- **八个字段**：身份、类型、版本、产出者、摘要、缺口、血缘、内容。
- **版本由黑板分配**：避免撞车/跳号；校验失败零副作用。
- **Basis vs 字符串**：结构给代码比较，字符串给模型看；避免解析漂移。
- **后序遍历**：先上游后下游，返回的列表可直接当修复顺序；有原因即过期。
- **只传 ref+summary**：省 token、防复述漂移；全文按需取。
- **深拷贝**：Payload 是引用类型，跨 Agent 共享可变状态必须隔离。
