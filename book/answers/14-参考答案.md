# 第 14 章 参考答案

## 练习 1：算一笔 token 账

粗略计算：

- 全文交接：一页 15KB，3 页 45KB；经过 4 个角色、每个角色平均重发 2 次历史，量级是 **几十万字节**。
- 引用交接：一个 `{ref, summary}` 大约 100 字节；一次 handoff 几十到几百字节，量级是 **几 KB**。

差距是两到三个数量级。具体 token 数取决于模型的分词器，但结论不变：**大产物不进上下文，成本是数量级的差异。**

## 练习 2：验证深拷贝

预期输出：

```text
{"text":"hello"}
```

如果把 `Get` 的深拷贝去掉，输出会变成：

```text
{"text":"Xello"}
```

因为 `Payload` 是 `[]byte`，`Get` 返回的是同一个底层数组的引用。

## 练习 3：版本漂移

1. `ref1 = outline@1`；
2. 写入 `outline@2`；
3. `Get(ref1)` 取到的是 **outline@1**；
4. `Get("outline")` 取到的是 **outline@2**。

所以流程引用必须带版本：它要能回到"当时看到的那一版"。不带版本的引用会在返工/重试时指向漂移，让日志和回放失真。

## 练习 4：设计一个 GC 策略

三条可能的规则：

1. **不删仍被引用的版本**：任何 live artifact 的 `BasedOn` 里出现的 `key@version` 都不能删；
2. **不删仍被流程持有的版本**：未完成的中断、checkpoint、回放日志里持有的 ref 不能删；
3. **只删"确定不再被任何 live 引用指向"的旧版本**：例如早于最近一次 checkpoint、且没有任何 live BasedOn 指向的版本。

为什么"简单按时间删"很危险：

- 一个长任务可能持有 `outline@1` 很久；
- 一个回放日志可能在几个月后才被读；
- 删掉后 `Get` 返回 `ErrArtifactNotFound`，恢复会失败。

更稳的做法是**引用计数**或**从根可达性分析**：从当前 checkpoint、pending 中断、live artifacts 出发，标记所有可达版本，其余才可回收。

## 练习 5：只读接口够不够

`schema.Reader` 只保证"不能写"，不保证"只能读某些 key"。

如果有一个不可信的第三方 Agent，可以设计：

```go
type ScopedReader struct {
    inner schema.Reader
    allow map[string]bool
}

func (r ScopedReader) Get(ref string) (schema.Artifact, error) {
    key, _, err := state.ParseRef(ref)
    if err != nil {
        return schema.Artifact{}, err
    }
    if !r.allow[key] {
        return schema.Artifact{}, fmt.Errorf("无权读取 %s", key)
    }
    return r.inner.Get(ref)
}
```

代价：

- 需要维护 allow 列表与生命周期；
- 需要审计"谁读了什么"；
- 权限变更后，旧的 ref 是否还有效？

这是"能力安全"的延伸：**不仅要不给写权限，还要按需裁剪读权限。**

## checkpoint 的简要答案

- **黑板 vs State**：State 是一次运行的变量；黑板是跨角色、带版本、可审计的产物存储。
- **只传 ref+summary**：省 token、防漂移、防 Supervisor 搬数据。
- **引用不可变**：`key@version` 永远指向那一版；否则返工/回放会漂移。
- **深拷贝**：Payload 是引用类型，共享可变状态会静默污染。
- **版本有洞**：`Get` 用下标取版本，会静默取错；错取比失败更危险。
- **不解决四件事**：payload 语义、调度、持久化、GC（也没有细粒度权限）。
- **没有字段可搬**：把约束放进类型，而不是 Prompt。
