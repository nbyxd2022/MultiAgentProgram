# 第 26 章 参考答案

## 练习 1：加一条用例

```json
{"id":"my-case","topic":"AI","tags":["smoke"],"expect":{"must_have_kinds":["research","outline","design","render"],"pages":3}}
```

```powershell
go run ./cmd/l4 -tag=smoke
```

预期：如果流程正常，它会通过；如果失败，报告会写清是哪条判据，例如：

```text
pages：期望 3，实际 2
```

以及 `must_have_kinds` 缺了哪些。

## 练习 2：空期望

`CaseSet.Validate` 会拒绝：

```text
用例 xxx 的 expect 一条判据都没有 —— 它会永远通过...
```

如果不拒绝：

- 这个用例永远绿；
- 没人会去看它；
- 它什么都没验证。

"永远绿"比"永远红"更危险：红会被修，绿会被信任。

## 练习 3：注入失败用例

```powershell
$env:L4_BAD_CASE="1"; go run ./cmd/l4
```

默认 3 条用例里：

- `baseline-3p` 通过；
- `expect-mismatch` 失败（故意）；
- `short-topic` 通过。

成功率 2/3 ≈ 66.7%。

注入 `injected-bad`（期望 99 页）后变成 2/4 = 50%。

这证明"汇总真的在算"，而不是一个固定值。

## 练习 4：软判据自愈

```powershell
$env:L4_JUDGE_REFUSES="1"; go run ./cmd/l4
```

第一次 `Judge` 返回：

```json
{"scores":{"creativity":100},"reason":""}
```

三样都坏：自创维度、分数越界、理由为空。

`ParseJudgement` → `Validate` 报错；`judgeOne` 把校验器的原话回灌；第二次返回合法 JSON。

`judgeStub.calls` 为 2，`healed` 为 1。

如果只看最终输出，一次成功的自愈和"从来没坏过"看起来一样——所以代码专门记录了 `healed`，让它可见。

## 练习 5：步数口径

去掉 `Layer` 过滤后，`Count(KindStart)` 会把：

- 图层的 4 条（4 个节点）；
- agent 层每个角色的 ReAct 迭代（可能 20+ 条）；

加在一起。

于是 `max_steps` 会报 30 左右，而实际只有 4 个节点。

修复应该在**指标层**：按 `Layer` 分流，`Steps` 只数图层，`AgentSteps` 数 agent 层。

不要改事件（两层发 start 都是对的），也不要改期望（期望问的是图跳数）。

## checkpoint 的简要答案

- **自比 vs 他比**：自比比较两次运行；他比比较运行与人的期望。
- **每个用例至少一条硬判据**：否则永远绿，没人看，什么都没验证。
- **跑完全部判据**：判据免费，运行不免费；一次报一条会浪费多次运行。
- **Steps vs AgentSteps**：图层节点数 vs 所有角色 ReAct 迭代数。
- **跑不完 vs 判据没过**：前者看错误，后者看产物；平均值只算跑完的。
- **软判据不进 Passed**：概率值会让评测 flake；它是线索。
- **自愈 vs retry**：改输入再问 vs 同一请求再发。
- **射程**：骨架/流程/成本能测；Prompt 质量、真实模型效果测不出。
