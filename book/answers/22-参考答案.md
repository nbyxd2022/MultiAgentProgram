# 第 22 章 参考答案

## 练习 1：临时文件

在 checkpoint 目录里创建 `ckpt-xxx.tmp`：

```powershell
New-Item -ItemType File out/l3/ckpt/ckpt-xxx.tmp
```

`List()` 只认 `.json` 后缀，所以不会列出它。

如果把它也列出来，调用方会去 `Load` 一个残缺副本——而它看起来和正常 run 一模一样。

这就是"存在 ≠ 完整"在存储层的应用：**能被列举出来的东西，必须真的可用。**

## 练习 2：非法 run id

| 输入 | 结果 |
|---|---|
| `demo` | 通过 |
| `../x` | 拒绝（`..` 与 `/` 都不允许） |
| `a/b` | 拒绝（`/` 不是安全字符） |
| `demo space` | 拒绝（空格不允许） |
| `""` | 拒绝（不能为空） |
| 超长 id | 拒绝（上限 128 字节） |

为什么不清洗：

- `a/b` 和 `a_b` 都会被清成 `a_b`；
- 两个不同的 run 共用一个文件；
- 后写的顶掉先写的，且无人知晓。

拒绝把问题暴露在调用方，而不是变成数据事故。

## 练习 3：checkpoint 的体积

每次 `Save` 写的是**全量** State，包括整个黑板的所有版本。

如果产物是 100 页 HTML：

- 每页 15KB，100 页就是 1.5MB；
- 多个版本、每跑一个节点写一次，体积和写盘时间都会快速上涨。

优化方向：

1. 大产物外置（只存路径/引用）；
2. 增量日志（只写新增版本）；
3. 压缩；
4. 降低保存频率（但会牺牲恢复粒度）。

L3 的取舍是"还没到那一步"，但这条边界要写出来。

## 练习 4：模拟写盘中断

如果 rename 之前失败：

- 目标文件仍然是**旧的完整版**；
- 临时文件可能留下（进程被杀时清理代码不会执行）；
- 下次 `Load` 读到旧版；
- `List` 会忽略临时文件。

这正是原子写的目标：**任何时刻，磁盘上只有旧的完整版或新的完整版。**

## 练习 5：选架构

### 场景 A：每天 CSV → 报表，步骤固定，失败要重跑

选**固定流水线或图**。

- 步骤固定，不需要模型路由；
- 失败要能重跑，图 + checkpoint 更合适；
- 如果只是一次性脚本，流水线足够。

### 场景 B：开放式研究助手，用户问题决定查什么、查几轮

选**Supervisor**。

- 节点集合和顺序不固定；
- 模型需要根据中间结果决定下一步；
- 代价是路由不确定、难恢复。

如果还要审计和恢复，可以用"图 + Supervisor 节点"：外层流程固定，内层探索开放。

### 场景 C：客服工单，分类后走不同分支，要审计，人工可接管

选**图 + HITL + checkpoint**。

- 分支明确，适合图的边；
- 审计需要状态与事件；
- 人工接管需要中断与恢复；
- 分类节点内部可以用 LLM，但外层流程由代码保证。

## checkpoint 的简要答案

- **原子写五步**：临时文件、写、fsync、rename、fsync 目录。
- **同目录**：rename 只在同一文件系统内原子。
- **Windows 重试**：目标被占用会 ACCESS_DENIED；有界重试最多多花几毫秒。
- **只认 .json**：临时文件不是完整记录。
- **拒绝不清洗**：清洗会制造碰撞。
- **State 无游标/Topic**：完成和下一步都能从产物推导。
- **全量快照**：追加语义让全量等价于时间点，但体积/写盘成本高。
- **不该用图**：短任务、开放流程、不需要恢复/HITL、吞吐敏感、节点集合不稳定。
