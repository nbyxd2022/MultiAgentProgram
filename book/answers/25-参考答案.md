# 第 25 章 参考答案

## 练习 1：零值 fail-closed

```go
g := budget.New(budget.Limits{})
g.Allow(budget.Usage{Steps: 1}).OK // false
```

因为 `Limits{}` 的五维上限都是 0，而 `Allow` 投影后 `Steps=1 > 0`。

要允许一步，至少：

```go
budget.Limits{
    Steps:            1,
    PromptTokens:     budget.NoLimit, // 或者一个 >0 的值
    CompletionTokens: budget.NoLimit,
    CostMilli:        budget.NoLimit,
    Elapsed:          budget.NoWall,
}
```

注意：如果只把 `Steps` 设成 1，其余保持 0，`Allow(Steps:1)` 会通过（其余维的 need 是 0，0>0 不成立）；但一旦 `ReportUse` 报了 token，就会超限。所以"能跑"和"能跑完"是两件事。

## 练习 2：检查与记账

```go
g := budget.New(budget.Limits{Steps: 2, Elapsed: budget.NoWall, ...})

g.Allow(budget.Usage{Steps: 1}).OK // true
g.Allow(budget.Usage{Steps: 1}).OK // 还是 true —— Allow 不记账
g.ReportUse(budget.Usage{Steps: 1})
g.Allow(budget.Usage{Steps: 1}).OK // 仍然 true（1+1=2 <= 2）
g.ReportUse(budget.Usage{Steps: 1})
g.Allow(budget.Usage{Steps: 1}).OK // false（2+1=3 > 2）
```

这证明：**`Allow` 只是投影，不改变账本。** 记账必须显式 `ReportUse`。

## 练习 3：接上成本维

价格表应该放在**最外层装配/适配器**：

- 它依赖具体模型与价格，属于易变的外部知识；
- 放在 Agent 里会让 Agent 依赖价格表；
- 放在 budget 里会让 budget 认识模型。

一个形状：

```go
type PriceTable map[string]struct{ Prompt, Completion int64 } // 厘/千 token

func CostMilli(model string, p, c int) int64 { ... }
```

在 Agent 每次成功后：

```go
a.guard.ReportUse(budget.Usage{
    PromptTokens: int64(resp.Usage.PromptTokens),
    CompletionTokens: int64(resp.Usage.CompletionTokens),
    CostMilli: CostMilli(model, ...),
})
```

价格变了只改价格表。

失败调用没有用量，只能：

- 估算（比如按上一次成功调用的平均）；
- 或者让 `Client` 在错误里带 usage；
- 或者接受"失败成本不可见"。

## 练习 4：并发与预留

`Allow` / `ReportUse` 分离在并发下会出现 TOCTOU 窗口：

- 两个 goroutine 同时 `Allow`，都看到"还剩 1 步"；
- 都通过；
- 都执行；
- 总共用了 2 步。

修法：

1. **事前预留 + 事后结算**：`Allow` 原子扣减，`ReportUse` 只补差额；
2. **原子扣减**：`Reserve(n)` 在锁内完成检查与扣减；
3. **接受多放一次**：如果超限代价可接受。

并行还会影响事件顺序、失败隔离、合并语义——第 12 章说过，这不是"加个 goroutine"。

## 练习 5：预算提示

`Decision.Notice` 大致是：

```text
prompt_tokens 预算不够了（上限 100000，已用 99000，这一步要 5000）——
请基于已有的信息收尾，不要开始新的步骤
```

它是给**模型**看的，必须告诉模型"该怎么办"。

如果只说"预算不足"，模型可能继续尝试，直到被强制终止。

## checkpoint 的简要答案

- **五维**：steps / prompt / completion / cost（厘）/ elapsed。
- **零值 fail-closed**：忘记配预算应该"跑不了"，不是"无限花钱"。
- **检查/记账分离**：事前不知道真实用量；事后记账才准确。
- **时间由执行者报**：守卫只做加法，不看时钟；墙钟是另一个判据。
- **不能开豁免**：理由同样适用于别的维度，就是开后门。
- **成本维没有生产者**：字段存在，但没人报；是"看起来有、实际没有"。
- **失败也花钱**：失败调用没有 usage，账本少记；需要改 Client 契约或估算。
