# 第 24 章 参考答案

## 练习 1：加一个 `UserID` 字段

`UserID` 不命中正文词表（没有 Prompt/Response/Args/...），所以反射测试会要求 `Redact` **保留**它。

但如果它是 PII，保留就是错的。

这说明：

- 命名约定能强迫你面对"这个字段属于哪一侧"；
- 但它不能替你判断"这个字段敏不敏感"。

可选做法：

1. 把字段改名为 `UserContent`（命中 `Content`，被清空）——语义可能不准确；
2. 给 `Event` 加 `Sensitivity` 分类，`Redact` 按分类决定；
3. 单独写一个 `RedactPII`，对元信息里的 PII 做二次处理。

## 练习 2：把 `Detail` 加回白名单

在 `Redact` 里加 `Detail: e.Detail` 后，`TestRedactPreservesEveryMetaField` 会失败。

因为测试的 `bodyLike` 列表里包含 `Detail`：

```go
bodyLike := []string{"Prompt", "Response", "Args", "Payload", "Body", "Content", "Detail"}
```

它会断言 `Detail` 必须被清空。失败信息会指出"字段 Detail 是正文，Redact 却没清空它——它会被发到上游"。

为什么代码评审不一定能抓住？

因为 `Detail` 这个名字**听起来像元信息**。测试按名字 + 类型判断，不靠人的直觉。

## 练习 3：本地完整、远端脱敏

```go
local := observ.NewRecorder()
remote := observ.NewRecorder()
tracer := observ.LocalAndRemote(local, remote)

tracer.Trace(observ.Event{
    Layer: observ.LayerTool, Phase: "render", Kind: observ.KindToolResult,
    ToolName: "web_search",
    ToolArgs: `{"query":"secret"}`,
    Detail:   "工具返回了完整正文",
    UserPrompt: "用户的问题",
})
```

预期：

- `local.Events()[0]` 里 `ToolArgs`、`Detail`、`UserPrompt` 都有值；
- `remote.Events()[0]` 里这三个都是空；
- `ToolName`、`Phase`、`Kind` 在两边都有；
- 顺序上 local 先收到（`Fanout` 按参数顺序）。

## 练习 4：把秘密放进 `Err`

当前 `Redact` **保留** `Err`。

如果 `Err` 是：

```text
读取文件 C:\users\alice\secret.txt 失败
```

脱敏后仍然会发出去——这算泄露。

可选处理：

1. 在生成 `Err` 时只写"读取文件失败"，不拼路径；
2. 单独写 `SanitizeErr`，在 `Redact` 里调用；
3. 把 `Err` 也归为正文（但会丢失失败分类信息）；
4. 用结构化的错误码代替自由文本，细节只进本地日志。

这是一个典型的"元信息里也可能有秘密"的例子。

## 练习 5：设计一个敏感性分类

```go
type Sensitivity string

const (
    SensitivityPublic   Sensitivity = "public"
    SensitivityInternal Sensitivity = "internal"
    SensitivitySecret   Sensitivity = "secret"
)
```

关系：

- `Redact` 只复制 `Sensitivity != Secret` 的字段；
- 或者只复制 `Public` / `Internal` 的字段，`Secret` 一律清空；
- 设置者必须是**产生这个字段的那一层**（它最清楚内容）；
- 如果设置错（把 secret 标成 public），脱敏就失效——所以默认值必须是"最保守"的。

这比命名约定更强，但也更重：每个字段都要有人负责打标。

## checkpoint 的简要答案

- **两个出口要求相反**：本地要完整排查，远端要脱敏防泄露。
- **白名单**：漏正文会泄露且不报错；漏元信息后果轻且容易发现。
- **Detail 改成正文**：它装的是工具回执/错误原文，不是一句话元信息。
- **反射测试守元信息侧**：白名单漏正文是安全的，漏元信息才是静默丢失。
- **只对字符串生效**：`PromptTokens` 是数值，不能被 `Prompt` 误判。
- **本地在前**：不可重建的先拿。
- **脱敏不解决**：加密、访问控制、元信息泄露、侧信道。
