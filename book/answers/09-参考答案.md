# 第 9 章 参考答案

## 练习 1：给 Extract 补测试

```go
func TestExtractObject(t *testing.T) {
    cases := []struct {
        name string
        in   string
        want string
    }{
        {"字符串里的右括号", `{"a":"}"}`, `{"a":"}"}`},
        {"嵌套对象", `{"a":{"b":1}}`, `{"a":{"b":1}}`},
        {"截断", `{"a":1`, ``},
        {"取第一个", `你好 {"a":1} 再见 {"b":2}`, `{"a":1}`},
    }
    for _, tc := range cases {
        t.Run(tc.name, func(t *testing.T) {
            if got := llmjson.ExtractObject(tc.in); got != tc.want {
                t.Fatalf("got %q, want %q", got, tc.want)
            }
        })
    }
}
```

预期：

- 第一个用例验证"引号里的 `}` 不是结构"；
- 第二个验证嵌套配平；
- 第三个验证截断返回空串，而不是半截；
- 第四个验证只取第一个完整对象。

## 练习 2：写一个 `ParseAndValidate`

```go
type ParseStage string

const (
    StageSyntax   ParseStage = "syntax"
    StageSemantic ParseStage = "semantic"
)

func ParseAndValidate(raw string, out any, validate func() error) error {
    cleaned := llmjson.Clean(raw, false)

    if err := json.Unmarshal([]byte(cleaned), out); err != nil {
        return fmt.Errorf("[%s] 解析失败: %w（原始输入: %s）",
            StageSyntax, err, truncate(raw, 300))
    }
    if validate != nil {
        if err := validate(); err != nil {
            return fmt.Errorf("[%s] 校验失败: %w", StageSemantic, err)
        }
    }
    return nil
}
```

关键点：

- 错误信息里带**阶段**，调用方和模型才知道是"格式不对"还是"内容不对"；
- 解析失败时带上原始输入（截断后），否则你永远不知道模型到底给了什么；
- `Clean` 之后仍然必须 `Unmarshal`，不能假设它是合法 JSON。

## 练习 3：追踪一条坏输入

输入：

```text
好的，结果如下：
```json
{"issues":[{"level":"major","message":"第二条太空","fix":"补数据"},]}
```
```

| 问题 | 处理层 | 结果 |
|---|---|---|
| Markdown 包裹 + 前置文字 | `ExtractObject` | 抠出 `{...}` |
| 尾逗号 | `Repair` | 去掉 `,}` 里的逗号 |
| 缺 `field` | `Validate` | 报"field 不能为空" |
| 整个输入被截断 | `finish_reason=length` / `Unmarshal` | 不要试图修，重试或加长输出 |

注意：前两个问题可以在同一轮里被修掉；第三个问题必须回灌给模型；第四个问题在更早的 Agent 层就该被拦住。

## 练习 4：该修还是该重试？

| 情况 | 处理方式 | 理由 |
|---|---|---|
| `finish_reason=length` | 重试 / 加长 `max_tokens` / 分段输出 | 输出没写完，修复无法恢复丢失的内容 |
| `field` 为空 | 回灌给模型，让它补 | 语义缺失，代码不能替它编 |
| JSON 外面多一句"好的" | `Extract` | 语法层问题，结构本身完整 |
| `level="严重"` | 回灌给模型，枚举校验 | 语义/契约问题，不能靠字符串替换猜 |

一个判断口诀：

> **能靠"去掉多余的东西"解决的，才叫修；需要"补上不存在的东西"的，必须重试或回灌。**

## checkpoint 的简要答案

- **Extract vs Repair**：前者从混合文本里找完整结构，后者修小格式毛病；先 Extract 再 Repair，否则会把前置文字当 JSON 修。
- **返回原文**：下游报错能看到模型真正给了什么；空串/`{}` 会掩盖线索。
- **Clean 后还要 Unmarshal**：Clean 不保证合法，只保证尽力且不丢原文。
- **四层**：语法（llmjson）、结构（Unmarshal）、语义（Validate）、截断（Agent 层）。
- **完整修复库**：行为不透明，容易让人放弃看原文；只修确定的几种更安全。
- **structured outputs**：能减少语法错，不能替代语义校验，也不能证明"真的检查了"。
