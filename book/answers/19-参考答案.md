# 第 19 章 参考答案

## 练习 1：让节点永远重做自己

```go
func (n *LoopNode) Run(ctx context.Context, in graph.NodeInput) (*graph.Outcome, error) {
    return &graph.Outcome{Next: n.Name()}, nil
}
```

预期：

- 节点实际执行 **4 次**；
- 第 5 次进入循环时，`runs[name] = 5 > 4`，返回错误；
- 错误信息包含"它在反复要求重做自己，请检查它的重做判据是否无界"；
- 如果节点每次产出新版本，这些版本都还在黑板上。

注意：上限是 4 次执行，不是 4 次重试（第 1 次执行 + 3 次重做）。

## 练习 2：Product + Interrupt

```go
return &graph.Outcome{
    Product:   somePayload,
    Interrupt: &it,
}, nil
```

预期：

- Runner 返回 `StatusInterrupted`；
- checkpoint 的 `Pending` 里包含 ID、Node、Attempt、Kind、Prompt、ExpiresAt；
- 下一次 confirm 后，`CanSkip` 会跳过这个节点（产物已存在且新鲜）；
- 调度直接从下游继续。

## 练习 3：只有 Interrupt

```go
it := in.Interrupt("ask-node", graph.KindAskUser, "请给一个主题")
return &graph.Outcome{Interrupt: &it}, nil
```

预期：

- `ask_user` 的 `RequiresNote = true`；
- confirm 时 `Note` 为空 → `Decision.Validate` 报"回答不能为空"；
- 带 Note 的 confirm 通过后，节点下一次执行时 `NodeInput.Answer` 非 nil，能读到 Note；
- 如果节点忽略 Answer，只重跑自己，可能再次中断——这是节点实现的问题，不是协议的问题。

## 练习 4：节点 panic

```go
panic("boom")
```

预期：

- Runner 不崩溃，返回 error；
- 错误里包含"这是一个 bug，不是外部故障"和 stack；
- 已完成的 checkpoint 仍然可读；
- 修好节点后再 `Run`，已完成节点会被 `CanSkip` 跳过。

## 练习 5：节点返回 error

```go
return nil, fmt.Errorf("模拟失败")
```

预期：

- `StatusAborted`，error 返回；
- 之前的产物仍在黑板上/checkpoint 里；
- 再 `Run` 会从第一个不能跳过的节点开始，通常是失败的那个节点。

注意：Runner 不会自动重试失败节点；重试策略由节点自环或调用方决定。

## checkpoint 的简要答案

- **共用 drive**：位置由产物推导，没有游标，恢复只是"再读一次状态"。
- **Outcome 组合**：Product only；Product+Interrupt；Interrupt only；Product+Next；etc.
- **自环上限**：防止无界重试；上限 4 是"够用但能拦住跑飞"的折中。
- **预算触顶不返回 error**：那是系统自己的决定，返回 error 会让调用方丢掉已完成产物。
- **每节点落盘**：进程被杀也不丢已完成部分。
- **panic vs error**：panic 是代码 bug，带 stack、不重试；error 是执行失败，可以修好后重跑。
- **Runner 不做**：并行、自动重试失败节点、补偿事务、同进程内断点续跑。
