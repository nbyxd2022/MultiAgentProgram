# 第 20 章 参考答案

## 练习 1：跑一次完整的中断

```powershell
go run ./cmd/l3
```

预期：

- 跑到 `outline` 后停下，打印确认问题；
- 进程正常退出，状态是 `interrupted`；
- checkpoint 文件里 `Pending` 非空，`Decision` 为 nil；
- `Attempt` 是 `outline` 当前版本数 + 1（第一次是 1）。

## 练习 2：确认后继续

```powershell
go run ./cmd/l3 -answer=confirm
```

预期：

- 新进程从磁盘恢复；
- `outline` 不会重新执行（产物已在黑板，`CanSkip` 跳过）；
- `Ran` 列表里通常只有下游节点；
- confirm 不需要额外逻辑，因为它只是"再读一次状态"。

## 练习 3：修改后重做

```powershell
Remove-Item -Recurse -Force out/l3/ckpt
go run ./cmd/l3
go run ./cmd/l3 -answer=revise -note="第二页改成讲成本"
```

预期：

- `outline` 被强制重做（`plan.Force`）；
- 新产物版本 +1；
- 下游依据 `outline@1` 的产物被 `StaleReasons` 标记过期，按顺序重做；
- `Note` 通过 `SubAgentNode.hintWithAnswer` 变成节点的额外要求。

## 练习 4：放弃

```powershell
go run ./cmd/l3 -answer=abort
```

预期：

- 状态是 `aborted`；
- 已完成的产物仍在；
- 交付说明会明确这是"带着已完成的部分收尾"，不是失败。

## 练习 5：把 attempt 改成计数器

假设 `AttemptFor` 改成运行期计数器 `count++`：

- 第一次中断 ID 是 `run:outline:1`；
- 恢复后节点重跑，计数器从 0 开始（新进程）或继续 +1；
- 如果变成 `run:outline:2`，而人的答案挂在 `run:outline:1` 上，系统会认为"这次问题没人回答"，于是**再次提问**；
- 用户会看到"我已经回答过了，为什么还问我"。

这就是"确定性 ID = 可重放"的反面教材。

## checkpoint 的简要答案

- **只实现先产出再问**：confirm 可以靠 `CanSkip` 自然继续；ask_user 需要节点理解 Answer，暂不需要。
- **先产出再问**：产物已在黑板，confirm 后自然跳过，不需要特殊逻辑。
- **ID 确定性**：`runID:node:attempt`；attempt 从黑板版本数 +1 推导，不是计数器。
- **Decision 先落盘**：崩溃后磁盘上仍是"已回答未消费"，下次自动重放。
- **三种意图**：confirm 继续；revise 强制重做并带 Note；abort 停止并降级交付。
- **业务过期 vs 存储 TTL**：业务过期进数据，能报 `expired`；存储 TTL 只负责回收。
- **五种失败**：confirm 无产物、随机 ID、答案只在内存、不支持 abort、过期报成不存在。
