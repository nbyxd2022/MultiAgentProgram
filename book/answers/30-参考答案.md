## 5 分钟汇报稿

```text
1. 我想学 Agent 运行时，不是学某个框架的 API。
   所以用 Go 手写了一条从单 Agent 到图编排的路线。

2. 架构：
   - L0：ReAct + 工具；
   - L1：结构化产物 + 评审；
   - L2：Supervisor + 黑板 + 失效传播；
   - L3：图 + HITL + checkpoint；
   - L4：事件 + 预算 + 评测。

3. 三个取舍：
   - 不用框架，为了理解框架替我做了什么；
   - L2→L3：从"检查顺序"到"结构上不可能违反"；
   - 产物只传引用，不传全文。

4. 证据：
   - build/vet/test 全过；
   - l3 能演示跨进程恢复；
   - l4 smoke 能跑评测。
   - 真实模型评测、真实检索、并行还没做。

5. 边界：
   不是生产级；Runner 串行、文件存储、搜索是 Mock、成本维没生产者。
```

## 必答题的简要答案

### 为什么不用 Eino/LangGraph？

为了理解框架替我做了什么；生产会用框架，并能说清它隐藏了什么。

### 最难修的 bug？

选一个真实故事，讲清"发现 → 根因 → 修法 → 防回归"。例如 `Detail` 被误判为元信息导致脱敏泄露。

### 100 倍流量哪里先崩？

串行 Runner、全量文件 checkpoint、无并行限流、无多租户、Mock 检索的延迟。

### 量化了什么？

测试数量/覆盖率、l3 恢复一致性、l4 smoke；真实模型的前后对比还没做。

### 是生产级吗？

不是。它是学习实现，证明了机制，没有证明生产可用性。

### AI 帮写的吗？

是参考实现 + AI 辅助；我能解释/重建的部分是我负责的，讲不清的不写进简历。
