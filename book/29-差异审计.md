# 第 29 章 你的版本 vs 仓库：一次差异审计

别人的代码读完了，现在把镜头转回来：你自己的版本和仓库差在哪？哪些是简化，哪些是漏掉？

## 29.1 审计不是"找不同"

一份有用的审计，每一条差异都要回答三件事：

1. 这是什么差异？（能力 / 简化 / 缺陷 / 欠账）
2. 它防住了什么故障？
3. 处置是什么？（改 / 登记 + 触发条件 / 保留 + 理由）

只列"仓库有、我没有"没有意义——你本来就不需要复制所有东西。

## 29.2 你的第 3 章 vs 仓库 L0

第 3 章的 Agent 是一个最小可运行版。逐项对比：

| 能力 | 你的版本 | 仓库 L0/L3 | 差异性质 | 处置 |
|---|---|---|---|---|
| ReAct 循环 | 有 | 有 | — | — |
| 多工具调用 | 有 | 有 | — | — |
| 工具错误回灌 | 有（简单 JSON） | 有（`formatToolError`） | 你的错误信息更弱 | 改进 |
| 最大步数 | 有 | 有 | — | — |
| 重试 | 无 | 有 `retry`，但**没接线** | 欠账 | 接上并测试 |
| 超时 | 无 | 有 HTTP 超时 | 缺能力 | 补 context/client timeout |
| 消息领域/线格式分离 | 无（合在一起） | 有 | 简化 | 保留，知道代价 |
| 事件 | 无 | 有 `observ` | 缺能力 | 至少加一个 Recorder |
| 预算 | 无 | 有 `budget` | 缺能力 | L4 再补 |
| 产物/版本/血缘 | 无 | 有黑板/信封 | 缺能力 | L2/L3 再补 |
| 持久化 | 无 | 有 checkpoint | 缺能力 | L3 再补 |
| 多 Agent | 无 | 有 Supervisor/图 | 缺能力 | L2/L3 再补 |
| 评测 | 无 | 有 eval（较薄） | 缺能力 | L4 再补 |

这张表的关键不是"你少了多少"，而是每一格的性质：

- "消息领域/线格式分离"是有意的简化，你知道代价就行；
- "重试没接线"是欠账，不是"没实现"；
- "事件/预算/评测"是后续阶段，不是现在的缺陷。

## 29.3 审计仓库自己的声明

仓库也有很多"说了但没做到"的地方。`docs/10-L4复盘.md` 列了 11 个"声明 ✅ 实现 ✅ 生产 ❌"，其中几个最典型：

### 1. `CostMilli` 没有生产者

- 字段、类型、校验都在；
- 非测试代码里只有 `Add`、`NoLimit`、`remaining`；
- 没有一处赋过真实金额。

后果：成本维永远是 0。

### 2. `KindReconcile` 没有生产者

- 常量、契约表、注释都在；
- **没有一处 `emit(KindReconcile)`**。

后果：对账这个"最值钱的指标"是个空壳。

### 3. 重试没有接线

`retry` 包有实现、有测试，但 `cmd/*` 没有给 Agent 配 `Retry`。

默认是"试一次"——所以所有 Demo 实际上都不重试。

### 4. `LocalAndRemote` 没有生产调用

脱敏能力有实现、有测试，但没有远端出口接上它。

### 5. `Layers()` 只是候选

`Runner` 串行，`Layers()` 只被 `Describe()` 用来打印。

源码里专门写了警告：不要把候选当已支持。

### 6. 文档漂移

`budget.go` 开头写"四维"，而实际是五维；`Limits` 注释也有旧字样。

代码是对的，文档是旧的。

### 7. 根 README 可能过期

如果状态表还停在 L1/L2，而代码已经到 L4，读者会得到错误的印象。

文档不是代码的附属品——它也是交付物，也会说谎。

## 29.4 审计的三张表

### 表一：能力矩阵

| 能力 | 有实现 | 有测试 | 有生产调用 | 备注 |
|---|---|---|---|---|
| ReAct | ✅ | ✅ | ✅ | |
| 重试 | ✅ | ✅ | ❌ | 没接线 |
| 脱敏 | ✅ | ✅ | ❌ | 没接远端 |
| 成本 | ✅ | ✅ | ❌ | 没生产者 |
| 对账 | ✅ | ✅ | ❌ | 没生产者 |
| 并行 | 候选 | — | ❌ | `Layers` 只打印 |

这张表比"完成了 7/7"有用得多。

### 表二：差异处置

| 差异 | 类别 | 处置 | 触发条件 |
|---|---|---|---|
| 429 不可重试 | 缺陷 | 加 `HTTPStatusError` | 现在 |
| 失败调用不记账 | 欠账 | 改 Client 契约 / 估算 | 出现成本对账 |
| 文档四维/五维 | 缺陷（文档） | 改注释 | 现在 |
| README 状态过期 | 缺陷（文档） | 更新 | 现在 |
| 并行未实现 | 取舍 | 保留 | 节点数 × 耗时超阈值 |

### 表三：你的版本

| 你的简化 | 代价 | 什么时候必须补 |
|---|---|---|
| 消息类型合一 | 换厂商要改业务 | 接第二个模型厂商 |
| 无事件 | 无法复盘/评测 | 要做评测时 |
| 无持久化 | 进程挂了不能恢复 | 长任务 |
| 无预算 | 可能烧钱 | 接真实模型 |

## 29.5 审计的四个问题

对每一个模块，问四句：

1. 它防住了哪个具体故障？ 说不出来，可能是过度设计。
2. 删掉它会发生什么？ 说不出来，可能是空壳。
3. 有没有一条会失败的测试？ 没有，可能只是声明。
4. 谁生产、谁消费？ 没有生产者，就是空壳。

这四个问题能查出大部分"看起来有、实际没有"。

## 29.6 一次真实的审计示例

以"重试"为例：

它防住了什么？

- 模型调用的一次网络抖动/限流，不应该让整个任务失败。

删掉它会发生什么？

- 一次瞬时 5xx 就让整轮失败；
- 但当前 Demo 用离线替身，不会失败，所以删掉也看不出来。

有会失败的测试吗？

- `retry` 包有；但"Agent 真的会重试"没有——因为没接线。

谁生产、谁消费？

- 生产者：`Agent.Options.Retry`（没人设置）；
- 消费者：`retry.Do`（在 Agent 里）；
- 结论：机制存在，生产缺失 → 欠账。

处置：

- 在装配层加 `Retry: retry.Policy{Attempts: 3, Backoff: retry.Fixed(500ms)}`；
- 加一个"第一次失败、第二次成功"的测试；
- 记录"重试只包模型调用，不包工具"。

## 29.7 练习

先自己做，再看 `answers/29-参考答案.md`。

### 练习 1：填能力矩阵

选三个模块（比如工具、事件、预算），填：

```text
有实现 / 有测试 / 有生产调用 / 备注
```

回答：哪个模块是空壳？哪个是欠账？

### 练习 2：审计你的第 3 章

用 29.2 的表，给你的版本填一列。

回答：

- 哪些差异是"有意简化"？
- 哪些是"漏掉"？
- 哪一项最值得先补？

### 练习 3：找一条文档漂移

在本仓库找一个"注释/文档与代码不一致"的地方。

回答：

- 哪句话是错的？
- 它会让读者产生什么误解？
- 怎么改？

### 练习 4：给一条差异写处置

挑一条差异，写：

```text
差异：
类别：缺陷 / 欠账 / 取舍
处置：
触发条件：
验证方式：
```

### 练习 5：删掉一个机制

选一个你实现的机制，删掉它，跑一次。

回答：

- 有没有测试变红？
- 如果没有，说明什么？
- 你应该补测试，还是删掉这个机制？

## 29.8 小结与自检
合上书，回答：

- 一份有用的审计，每条差异要回答哪三件事？
- 你的第 3 章与仓库 L0 的主要差异有哪些？
- 仓库里有哪些"声明有、生产无"的空壳？
- 审计一个模块的四个问题是什么？
- 为什么"有测试"不等于"有生产调用"？
- 文档漂移为什么也是缺陷？
- 一条差异的处置应该怎么写？

能答出五题以上，再进最后一章。

## 29.8 拓展：给你的版本填一张矩阵

给第 3 章的 Agent 填一张表：有实现 / 有测试 / 有生产调用。哪一格是空的？那个空就是下一步。

如果三格都填满了，再加一列“有评测”：你怎么知道它改好了？这一列通常是最后才填上的。
