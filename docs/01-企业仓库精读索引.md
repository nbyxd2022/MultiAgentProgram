## 三、企业仓库已知的设计隐患（我们的改进靶子）

> 这些是我们在"手写版"里要**主动解决**的问题。注意：它们不代表代码质量差，
> 而是**多 Agent 系统在规模变大后普遍会遇到的难题**——正是面试考点。

### 3.1 编排层

| 编号 | 问题 | 证据 | 风险 |
|---|---|---|---|
| **A1** | 路由全靠 LLM 自然语言，无确定性兜底 | `main_chat_agent/system_prompt.md` | 路由误判、无法测试、无法统计准确率 |
| **A2** | 子 Agent 只能回传 Supervisor，全经中转 | `supervisor.go:50` + Prompt 要求"逐字段提取重组" | **让概率模型做无损数据搬运** → 丢字段、截断、改写 |
| **A3** | Supervisor 职责过载（既路由又搬 JSON） | 同上 Prompt 大半篇幅在讲格式透传 | 关注点不分离、Prompt 膨胀 |
| **A4** | 硬编码 Agent 名 + 文本嗅探 | `controller/chat.go:288` `dest == "recognize-ppt-agent"`；`:306` 正则抽 JSON | 改名/格式微调即静默失效 |

### 3.2 上下文与记忆

| 编号 | 问题 | 证据 | 风险 |
|---|---|---|---|
| **B1** | Rewriter 只留周期内最后一条 assistant 消息 | `supervisor.go:75` | 早期产物被裁掉 |
| **B2** | 摘要有损，缺"关键约束 pin" | `hotcold.go:674` `findCutoffFromEnd` | 用户硬约束（页数/必含页）在多轮摘要中丢失 |

### 3.3 终止与预算

| 编号 | 问题 | 证据 | 风险 |
|---|---|---|---|
| **C1** | 无全局 step / token / 成本预算 | `controller/chat.go:181` `RunnerConfig` 无 MaxStep；`:275` 循环无上限 | 互相 transfer 打乒乓 → 死循环、成本爆炸 |
| **C2** | 有工具级重试，缺 Agent 级失败升级链 | `GetModelRetryConfig()` 只重试 LLM 调用 | 子 Agent 整体失败时无明确策略 |

### 3.4 可观测与评测

| 编号 | 问题 | 证据 | 风险 |
|---|---|---|---|
| **D1** | 无评测集 / golden set | 仓库无 eval 目录 | 改 Prompt 无法量化回归 |
| **D2** | 路由决策不可统计 | `chat.go:291` 仅日志 | 无法算路由准确率 |

### 3.5 HITL 与状态

| 编号 | 问题 | 证据 | 风险 |
|---|---|---|---|
| **F1** | 中断信息依赖类型名，缺版本兼容 | `interruptstore/redis.go` 的 `TypeName` + 两处 `switch`；`schema.Register` | 加一种中断类型要改**四处**手写分派（`InterruptInfo` 字段 / `Set` / `Get` / controller 的 if-else），而四处之间**没有编译期约束**；无版本号 → 旧记录只能 `unknown type` 崩溃 |
| **F2** | 恢复只当"简单确认"，不支持修订 | `confirm_outlines.go` 只收一个 `UserAnswer` | 用户说"删掉第 3 页"无法处理 |
| **F3** | 续期发现锁丢失后**只记录、不中止** | `sessionlocker/redis.go:91-93`：`res == 0` 时只 `Warnf("lock lost during renewal")` 然后 `return`（停止续期），**请求继续跑、继续写** | 与 L1-3 / L2-11 是同一个病（**重要事实被降级成日志 = 等于没发生**）；锁失效后**两个执行者同时写同一 session** —— 正是这把锁本来要防的事 |
| **F4** | 同一个 store **两种写入语义并存** | `sessionstore/mongo.go`：`Set` 是 `ReplaceOne`（**全量替换**），`Delete` 是 `UpdateOne $set`（**局部更新**） | 用 `Set` 做局部更新会把未携带的字段**静默重置为零值**；而 `Status` 的零值恰好是 `SessionStatusDeleted` → 忘记赋值的会话**静默变成已删除**；又因 `ListByUser` 默认过滤 `status != 0`，它**看不见但 `Get` 仍取得到**（"看不见但能用"） |

> **F1 的复核记录**（R28）：01 索引原文写的是"类型改名 → 旧 checkpoint 无法恢复"。
> 读完代码发现它的 `typeName` 其实是**字符串常量**而不是 `reflect.TypeOf` 的结果，
> 所以"改结构体名"并不会破坏它 —— 原描述略微夸大了。
> 但"**四处手写分派、无编译期约束**"这个问题是真实的，而且更根本。
> **教训：索引的结论也要用代码复核。**

## 4. R38 · 观测 / 限额 / 一条**缺席**（L4 的精读）

### 4.1 三处值得学的设计

| 位置 | 设计 | 要吸收的判据 |
|---|---|---|
| `types.go` 的 `TraceEvent` | **明细**（span/phase/status/duration）与**录播**（system_prompt / user_prompt / response）在**同一个结构**里 | ⚠️ 一个结构与"两个消费者"不矛盾 —— **对策是多个出口**（`OnTrace` 可关 / `OnTaskLogTrace` 不可关）：**同一事件的多个消费者，先问"保留要求"是否相同** |
| `metrics.go` 的 `NodeMetrics` | **无侵入观测**：agent 包不 import prometheus，回调由最外层注入；**每个 helper 内部判空**（"业务逻辑无需再包一层 if"） | 横切关注点的依赖必须**向外**；而 helper 判空是为了**中间层也能传 nil**（否则每个透传点都要记得判空 = R23 那条教训） |
| `internal/limiter` | `Allow`（检查，不记账）/ `ReportUse`（**成功才计入**）分离；**TOCTOU 窗口写在接口注释里**；`EmptyLimiter`（**未注册 ≠ 错误**）；`CompositeLimiter`（多窗口，任一触发即限流） | 预算的**检查与记账必须分离**（否则失败的运行也算钱）；而由此产生的窗口**要写在接口文档里** —— **能被审计的妥协才是决定**；**"不限额"是一个合法的空对象，不是 nil** |

### 4.2 两个小宝石

| 位置 | 它是什么 | 一句话 |
|---|---|---|
| `agents/prom.go` 的 `OnImageCountMismatch(pageIndex, expected, actual)` | **对账**：这一页声明了 N 张图、实际画了 M 张 | **观测里最值钱的一类不是"成功/失败"，是"对账"** —— 它捕捉的是**静默的错**（没报错、流程走完、但内容不对）。这正是我们从 L0 追到 L3 的那一类东西 |
| `internal/otelkit/http2curl.go` | 把一次 HTTP 请求转成**一行 curl 命令** | **可排查性不是"记了多少"，是"能不能一键复现"**（人工拼 URL+body 会拼错，而拼错还会误导） |

⚠️ **并列记一个"被标注的妥协"**：`NodeMetrics.OnRecordLastStatus` 的注释写着"**桥梁回调**" ——
它绕开函数式上报接口去写两个可变变量。**它被命名成"桥梁"、被注释解释，于是它是一个能被审计的妥协**，
而不是一个混在正常字段里的怪东西。
（与 `PipelineInput` 上的 **13 个 `json:"-"`** 是同一个现象：**不正常的东西要一个个标注出来**。）

### 4.3 ⚠️⚠️ 最重要的一条是一条**缺席**：它**没有评测集**

```
=== 数据/用例文件（jsonl / golden）===      （空）
=== testdata 目录 ===                      （空）
=== eval 相关目录 ===
  frontends\test_v5_single_page_ppt_bench   ← 唯一一个，是个**前端页面**
```

**48 个测试文件、Prometheus 指标、OTel span、限流器、8 个无侵入观测钩子 —— 而没有一个评测集。**

| 它有的 | 它没有的 |
|---|---|
| **在线可观测**（生产聚合 → 看板/告警） | **离线可评测**（改一次 Prompt → 一键看指标升降） |
| 单元测试（48 个，纯函数） | **带真实输入 + 期望输出的用例集** |
| 人工试用（那个 bench 页面） | **能重复跑的回归** |

> ### 它说明的不是"它做得差"，而是两个东西的**代价可见度**不同
>
> | | 可观测 | 可评测 |
> |---|---|---|
> | 谁需要 | **运维 / 值班** | **写代码的人** |
> | 什么时候付代价 | 上线后**持续** | **每次改动前** |
> | 不做的后果 | **立刻**（线上出事） | **缓慢**（"好像变差了，说不清"） |
> | 不做的后果**可见度** | 高（有人会来问） | **低（没人会来问）** |
>
> **"立刻的后果"永远赢过"缓慢的后果"** —— 所以可观测先被做出来，
> 而评测集**一直排在后面**。
>
> 而我们的 L4 验收标准（"改一次 Prompt → 一键看到指标升降"）
> **恰恰是它没做到的那一半** —— 那句话不是"可观测"的要求，是"**可评测**"的要求。

### 4.4 明确**不照抄**的

| 不照抄 | 理由 |
|---|---|
| **接 OTel / Prometheus** | L4 的重点是"**观测模型**"，不是"接哪个后端"。端口（`Tracer`）定好之后，写适配器是机械工作 |
| **`http2curl`** | 点子记下了，但我们现在没有"需要复现的对外调用" |
| **`OnRecordLastStatus` 那种桥梁** | 它的存在是因为那边是**回调式**上报 + `defer` 需要可变状态。我们的事件是**流式**的，不需要 |
| **"路由准确率"**（教学计划产出物 ② 里的） | 它在我们这里**恒为 1**（L3 把路由交给了 `Needs()`）—— **指标的清单要随架构变化，照抄会得到假指标** |
