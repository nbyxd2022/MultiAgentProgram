# 手写多 Agent 运行时（Go · 零依赖）

一个从零手写的多 Agent 运行时：**确定性图编排 · 产物版本与失效传播 · 可恢复 HITL · 预算守卫 · 统一事件观测 · 离线评测**。

`go.mod` 只有两行 —— **不用 Eino / LangGraph / 任何第三方库**。

---

## ⚠️ 先读这一节：它**没有**做什么

> **它还没有跑过真实模型的任务评测。** 所以它暂时**不能**回答
> "通过率多少、失败在哪、改完好了多少" —— 而那三个问题比"实现了什么机制"重要得多。

| 现状 | 事实 |
|---|---|
| **检索是 Mock** | `tools/web_search.go` 返回**硬编码片段**，`source` 写着 `"mock-search"`。一个"研究型"系统的检索是假的。 |
| **软判据是离线替身** | `cmd/l4` 的 `judgeStub` 按 prompt 长度给 3/5/8 分 —— 它不是在判断"好不好"，是在证明**那条通路通**。 |
| **评测集只有 3 条** | `internal/eval/cases.jsonl`。其中 1 条是**故意必红**的（用来证明判据能红）。 |
| **没有真实模型评测** | `cmd/l4` 用的是 `ruleClient`（确定性替身）。`llm.OpenAIClient` 写了，但没有一次真实评测记录。 |
| **没有 HTTP / 没有并发跑** | CLI 单进程、串行。那是刻意的（见文末"明确不做"）。 |

**为什么把这些放在最前面**：一个**承认自己没跑过**的项目，比一个**看起来完整**的项目更可信。

## 60 秒上手

```bash
go build ./...          # 零依赖，不需要下载任何东西
go test ./...           # 430 个测试函数 + 145 个子用例
go run ./cmd/l3         # 图编排 + HITL 中断 + 杀掉进程重启仍能恢复
go run ./cmd/l4         # 一键回归：3 个用例 → 通过 2 / 失败 1（那 1 条是故意的）
```

⭐ **最值得看的一条**：

```bash
go run ./cmd/l3 -verify
# ✅ **两层**都一致：产物逐字节 + **行为序列**逐字节
```

它跑两遍（含**真实的中断 → 恢复**），然后比两遍的产物**和行为**是否逐字节相同。
一个有模型、有中断、有跨进程恢复的系统做到这一点，说明**链上每一个决定都是对的**。

## 架构

```
cmd/l0  l1  l2  l3  l4          五个递进的演示（不是五个产品）
 │
 ├─ agents/    4 个角色 + 1 个渲染器（研究员 / 大纲 / 版面 / 评审 / 渲染）
 ├─ graph/     图编排：边由 Needs() 推导 · 调度循环 · 中断落盘 · 恢复
 │   └─ checkpoint/   原子写（temp → fsync → rename → fsync dir）
 ├─ agent/     ReAct 循环（工具调用 / 错误回灌 / 有界重试）
 │   ├─ llm/        OpenAIClient（任何 OpenAI 兼容服务）+ 重试 + 静默失败兜底
 │   ├─ retry/      策略可注入；**退避可被 ctx 打断**
 │   └─ errclass/   可重试性判定（让错误**自己说**，不抠字符串）
 ├─ schema/    产物协议（Kind 强类型 + 信封双向校验 + 版本）
 ├─ state/     黑板（版本由它分配）· 完成判据（存在 ∧ 完整 ∧ 新鲜）
 ├─ observ/    统一事件（Layer/Kind 词表 + Recorder/JSONL/Fanout + Redact）
 ├─ budget/    预算守卫（检查与记账分离 · 五维：步数/token×2/成本/执行时间）
 ├─ eval/      评测（用例集 JSONL + 硬判据 + 软判据端口 + 三态判定）
 └─ llmjson/   模型输出的 JSON 不可靠 → 先抠再修，修不了返回原文
```

---

## 五个层，而每一层都是**被上一层的失败逼出来的**

| 层 | 它解决的那一件真事 |
|---|---|
| **L0** | 一个 Agent 的最小循环：**终止双保险**、工具错误**回灌给模型**而不是抛给用户 |
| **L1** | 单一角色会**跑飞** → 结构化提交（`SubmitTool`）+ 硬约束 + 回灌自愈 |
| **L2** | 多角色 → **产物协议**（谁能读谁的）；失败**熔断**；预算**告诉模型** |
| **L3** | 进程会死、人要参与 → **可持久化状态 + 中断跨进程恢复 + 幂等与可重放** |
| **L4** | 机制齐了但**说不清好不好** → 统一观测 + 预算守卫 + **离线可评测** |

每一层的复盘都在 `docs/`（`04` / `05` / `07` / `10`），而那四份是**这个项目最有价值的部分** ——
它们记的不是"我实现了什么"，是"**它在什么情况下会错**"。

---

## 为什么手写（而不是用 Eino / LangGraph）

**不是为了"手写更牛"** —— 是为了**能解释框架替我做了什么**。

这个项目的目标是把机制吃透：一个 `Runner` 的调度循环、一次中断的落盘、一张预算表的口径。
生产环境我会用框架，并且能说清**为什么**用、以及它会替我兜住哪些我兜不住的东西。

## 明确**不做**的（以及触发条件）

| 不做 | 触发条件 |
|---|---|
| HTTP / SSE 服务 | 目标 JD 明确要求后端时 |
| 分布式 / 多副本 | 出现第二个运行实例时 |
| 向量数据库 | 关键词/BM25 先跑不通时（**先用最笨的**） |
| 接 OTel / Prometheus | 真要上生产监控时（端口已定，适配器是机械工作） |
| Docker / CI | 对 solo 项目加分接近于零 |

## 已知的真问题（未修，按优先级）

| # | 问题 | 为什么它要紧 |
|---|---|---|
| 1 | **没有真实模型评测** | 它挡住"通过率 / 失败分类 / 改进幅度"三个数字 |
| 2 | **检索是 Mock** | 一个"研究型"系统的检索是假的 —— 那是**最容易被一眼看穿**的地方 |
| 3 | `FinishReason` **已透传但没有消费者** | "输出截断"能被记录，但**还没有人读它** |
| 4 | `Usage.CostMilli` **没有生产点** | 成本维永远是 0（缺一张"token → 钱"的表） |
| 5 | `observ.KindReconcile` **没有生产点** | 对账机制是空壳（缺一个"声明 vs 实际"的对照点） |
| 6 | `maxRunsPerNode` 在 `cmd/l4` **不触发** | 角色不返回 `Outcome.Next`，那一层界只在测试里活着 |

⭐ 那 6 条不是"忘记做"，是**明确登记过的** —— 每一条都有触发条件（见 `docs/10-L4复盘.md`）。
